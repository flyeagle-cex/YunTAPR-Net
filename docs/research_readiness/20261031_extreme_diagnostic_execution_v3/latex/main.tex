\section*{1. 批准后的真实终态}
研究者明确批准V2固定代码\code{9d63713}与提案\code{0be1a2b4}。只做一次后台调度，原生解释器通过独立性门槛，正式目录与共享标签任务声明创建；随后在标签统计初始化的人口加载器中触及冻结元数据配额，控制器停止后续全部任务，未重试。

\key{九模型前向均未开始，训练标签统计未完成，没有新科学结果。}

\section*{2. 原因与准备遗漏}
冻结统计SQLite（轻量级关系数据库）档案为33,804,288字节。原人口加载器先做文件散列校验，再作只读数据库连接；按两次档案长度预留为：
\[
2\times33,804,288=67,608,576>67,108,864=64~\mathrm{MiB}.
\]
仅这两次预留已超过原单任务上限，尚未计入人口、样本清单、坐标和质量检查元数据。失败发生在第二次档案打开前，标签读取计量器尚未创建。先前准备没有完整核算这条依赖路径，属于本轮配额设计遗漏。

V2未将失败时元数据终端计数保存，不能事后伪造精确实际值。V3准备保守计入整份已批准的64 MiB／128打开上限；原数据库第二次打开被提前拒绝，原生数据库内部物理读取量未冒充逐字节实测。
