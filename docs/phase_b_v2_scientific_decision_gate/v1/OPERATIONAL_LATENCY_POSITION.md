分析时刻 a=T+30 min，对应目标 [T,T+30 min)，是回顾性窗口反演而非预测未来降水。B1 需要所有六帧，设其首次业务可获取时刻为 t_avail,k，则数据就绪时刻为 max_k t_avail,k；最终发布时间还包含排队、固定预处理、推理和输出写入。业务延迟应以 t_publish−a 明示，时钟统一 UTC，并分别记录组件与失败/缺帧比例。观测提前量不能替代这条链路。

[NASA 官方 IMERG 说明](https://gpm.nasa.gov/data/imerg)区分面向低延迟应用的 Early/Late 与面向延迟不敏感研究的 Final。该产品说明不能替代本项目具体文件的历史可获取日志；本文不据网页一般延迟宣称本地业务达标。

## 两种可审议论文表述

**A（推荐，待批准）**：“本研究基于满足观测截止时刻因果约束的静止卫星红外多时相资料，开展云南降水发生与条件强度分布的回顾性反演；其架构具有面向近实时部署的潜力，实际业务可获取性及端到端延迟尚待验证。”

A 允许保留部署研究动机，同时在摘要、Methods 和局限性中披露 date_created 晚于分析时刻、Final 标签角色及开发集重复使用。因果窗口内的回顾资料身份不因此被自动重筛。

**B（仅未来证据成立后另批）**：“系统在预先定义的业务时限内，使用当时可取得的六帧红外资料完成并发布概率反演产品。”

B 至少还需：产品具体版本/重处理与 date_created 的语义；可靠 UTC 发布/接收/入库/首次读取日志与版本 SHA；六帧共同可用时间；独立预声明延迟期限及达到率、p50/p95/p99和最坏延迟；跨天气与季节、缺测/故障/队列负载；在当时可获取资料上进行禁止后补的业务回放；真实部署硬件上端到端测量与输出审计。期限与评价窗口 NOT_YET_ESTABLISHED，不能临时选择有利值。

上述日志、回放和真实推理需要独立新授权，缺少证据不能靠改写论文、观测因果性、合成耗时或 IMERG 产品名称补齐。业务资格若要修改，应另建协议，不覆盖本矩阵。
