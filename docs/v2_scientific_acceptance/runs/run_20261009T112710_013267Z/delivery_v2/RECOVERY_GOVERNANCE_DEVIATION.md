# B1-v2 恢复治理偏差（独立审查）

本记录只整理已发生事实，不追认历史授权。技术对账通过不等于授权合规通过。

已发表的 `CHECKPOINT_AND_RESUME_SPEC.md` 第 22 行要求：“必须另有绑定具体 LAST SHA 和原授权祖先的研究者恢复批准。”然而，实际 B1-v2 epoch 14 LAST 恢复记录明确以原始 Phase-A 正式授权和持续目标作为依据，并声明记录生成时没有新的研究者科学决策。这与独立恢复审批要求存在差异；本次研究者也明确要求独立记录该差异。登记的恢复证据中没有可核验的、另行由研究者作出的 LAST-bound 恢复批准。Codex 生成的 authorization JSON、GitHub 远端提交和运行预检不能自行构成人类批准。

实际启动命令使用新的恢复执行绑定记录，其 SHA 为 `73d8e76649ac1310ff1a541cb7f0e7518c4ad527c8571113726b56312c7115a2`，远端提交为 `f269272c821b49c5226ddf6d75eeb7108522cd34`，核验时间为 2026-10-09T00:40:57.273183+00:00。这个执行绑定仍以原始授权为祖先，不是独立恢复审批。不得将“已发布且预检通过”改写成“研究者另行批准”。

工程方面：完整 epoch 14 LAST 的 SHA 为 `40f7f1204aba52815e1c8c2f3d2a5ce5d73da6b7b0297e1d79dc843cb3390649`；model、optimizer、scheduler、RNG 的实际恢复身份均有收据。两次未 checkpoint 的 epoch 15 尝试分别完成 3,095 和 382 次更新，全部丢弃；重跑的保留轨迹与这两个前缀逐项零容差一致。最终保留 88,876 次更新，全部尝试 92,353 次。上述证据支持恢复状态和保留轨迹的工程可追溯性，没有证明新的科学审批已经存在，也不将整段未来轨迹称为有未保存的逐步参照。

此前未经核验的“研究者已授权恢复”草稿、后续更正、原始字节归档和失败证据继续保留。本次不删除、不改写、不补签、不追认。文件锁相关中断及 Codex 外部日志读取造成的冲突必须与科学指标分开解释。

BEST 的时间关系：冻结 B1 BEST 是 Epoch 9（update=47,052），在完整 Epoch 14 LAST（update=73,192）和受影响的 Epoch 15 恢复之前已生成。因此本次 BEST 的参数并非由该恢复段训练得到；但后来完整训练历史、早停和确认没有更优 checkpoint 的过程仍经过恢复段，不将这一事实当作审批偏差不存在。逻辑 epoch 身份证据见 recovery_best_chronology_note.json，未制造文件生成时刻。

潜在影响：缺失独立恢复审批削弱治理合规性与研究者对失败后继续执行的控制；重放对账和冻结身份未变降低了轨迹改变、调参或结果挑选的工程风险，但不能消除治理偏差。没有证据据此判定模型数值结果一定失效，也不能自动认定其可接受。研究者需要分别判断技术证据可靠性、治理偏差处置，以及科学验收；本材料不批准 Phase-B。
