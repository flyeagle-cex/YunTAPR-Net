## 1. 硬约束的代码化

1. **只为前向推理写代码**：`infer_eval.py` 中不存在 `optimizer`、`backward()`、`loss.backward`、
   `optimizer.step`；模型一律 `.eval()`，batch 循环在 `torch.autocast('cuda', dtype=torch.bfloat16)`
   下做 forward，并 `_qlog_validate`（复用冻结 FP64 校验 `models/quantile_v2/outputs.py:26`）。
2. **独立进程**：`run-all` 是 supervisor，对每个 run 用
   `subprocess.run([python, -B, infer_eval.py, run, --run-id <id>], env=_run_env(run))` 启动独立进程；
   `_run_env` 设置 `PYTHONPATH=<该家族冻结副本>/src`、`PYTHONHASHSEED=<seed>`、
   `PYTHONDONTWRITEBYTECODE=1`、`CUBLAS_WORKSPACE_CONFIG=:4096:8`。
   `PYTHONDONTWRITEBYTECODE`/`sys.dont_write_bytecode` 确保**不在冻结副本里生成 `__pycache__`**。
3. **只读 2023/2024**：2025 拒绝由冻结读取器自身完成（`load_inherited` 的 `'2025' in Path(name).parts`
   检查、`Plan` 的 `start.year!=year` 等）；本代码不含任何 2025 路径、也不含 2025 分支。
4. **每次遍历前向只做一次**：每个 run 进程只创建一个 reader、一次 `Development` 遍历；
   `BatchReader`/`PassReader` 的 `scene_seen` 禁止重复 scene；输出目录已存在即拒绝覆盖（无 resume）。
5. **读取量可审计**：B2–B8 用冻结的 `SourceCache`+`SourceMeter`（逐文件 SHA、逐 pass 账本，
   运行后 `read_scope_actual` 记录 `meter.totals()`）；B0/B1 用冻结 `VerifiedReader`
   （每次读取在同一 handle 内做 SHA-256 校验），`FrozenBudgetStub` 只统计逻辑字节、**不写私有 run 目录**。
6. **不修改任何既有文件**：写入仅发生在 `phaseB_inference/outputs/<run_id>/`、`logs/`、
   `outputs/_dry_check/<run_id>/`。

## 4. 统一推理-评价协议

### 4.1 每 run 一次 Dev 遍历

```
for pos in range(0, N_dev, 8):
    batch = reader.batch('Development', ids[pos:pos+8]).to('cuda')
    with torch.autocast('cuda', dtype=torch.bfloat16):
        out = forward(model, batch)
    frozen_evaluator.add(...)            # 只为“验证门槛”复算既有指标
    point_accumulator.add(rate, valid, region, out.rain_prob, out.conditional_quantiles_log)
```

- 批大小 8 与历史完全一致（B0/B1 `engine.py:141`；B2 `b2_runner.py:208`；B3–B8 `engine.py:194`）。
- 顺序 == `plan.ids('Development')` 历史顺序；`BatchReader.scene_seen`/`Coverage` 语义保证 no-skip/no-dup。
- B0/B1 的 `Evaluator` 要求 `len(ids)==DEV_N`（10501）；因此在 2 场景冒烟时冻结 evaluator 被跳过（记录在 smoke 输出），
  全量 run 一定实例化并比较。
- 不创建优化器、不算 loss；`torch.inference_mode()`（B0/B1 历史）由 `torch.no_grad()`/detach 等价覆盖。

### 4.2 输出（每 run 一个 `outputs/<run_id>/result.json`）

1. **既有指标（验证门槛）** `recomputed_frozen_metrics`：由冻结 `Evaluation`/`Evaluator` 本体重算的
   `summary`（及 B2–B8 的 `groups`），与 `stored_summary` 逐项比较；
2. **新指标** `new_metrics`：
   - 点估计 A/B/C：`MAE/RMSE/MeanBias/Pearson_CC` + 原始累加和 `Σŷ,Σy,Σŷ²,Σy²,Σŷy`；
   - 混淆矩阵（Pred>r vs Truth>r，r∈{0.1,1,5,10,20}，严格 `>`）：TP/FP/FN/TN + POD/FAR/CSI/HSS；
   - 发生概率诊断 `OCC_P`：`P(rain>0.1) ≥ 0.5`（冻结 reliability 分箱规则）vs `Truth > 0.1`；
   - 候选 D：`P(R>r)=p·(1−F_cond(r))` 的阈值支持统计 + 支持子集混淆矩阵 + 严格 `>0.5` 对照；
3. `gate`：门槛明细（tolerance/计数/逐指标 diff/passed）；`status` = `COMPLETE` / `GATE_FAILED` / `FAILED`；

5. `compact_metrics.csv`：便于 Lead 汇总主表（每个点估计一行 + 每个 (候选,阈值) 一行）。

所有输出都带 `notes`：候选点估计一律 `NONE_OF_THE_POINT_ESTIMATES_IS_FROZEN_OR_SCIENTIFICALLY_APPROVED`，
新指标 `EXPLORATORY_POSTHOC_DESCRIPTIVE_ONLY`，2025 `FROZEN_NO_ACCESS`。

对每个 checkpoint，用该家族**冻结评价类本体**（不是重写公式）在完全相同的 id/顺序/批/输入/前向环境下重算，

## 6. 新指标（全部 EXPLORATORY POSTHOC，不冻结）

以冻结监督掩膜上的像素为总体（与门槛同一 N_valid），单位一律 **mm/h**：

- **连续指标**：`MAE = mean|ŷ−y|`、`RMSE = sqrt(mean(ŷ−y)²)`、`MeanBias = mean(ŷ−y)`、
  `Pearson_CC = (Σŷy−ΣŷΣy/N)/sqrt((Σŷ²−Σŷ²/N)(Σy²−Σy²/N))`；
  同时落盘 `Σŷ,Σy,Σŷ²,Σy²,Σŷy` 供独立复算（`PointAccumulator.sums`）。
- **事件混淆矩阵**：对 r∈{0.1,1,5,10,20}，`Pred = ŷ > r`（严格 >）vs `Truth = rate > r`（float32 严格 >）。
  `POD=TP/(TP+FN)`、`FAR=FP/(TP+FP)`、`CSI=TP/(TP+FP+FN)`、
  `HSS=2(TP·TN−FP·FN)/((TP+FP)(FP+TN)+(TP+FN)(FN+TN))`；
  TP+FP+FN+TN=N_valid（单测覆盖；训练/评价中绝不使用）。
- **发生率诊断** `OCC_P`：`p ≥ 0.5` vs `rate > 0.1`，与冻结 reliability 分箱 5..9 的语义一致
  （`metrics.py:75 bins=searchsorted(arange(1,10)/10,p,'right')` ⇒ bin≥5 ⇔ p≥0.5，含 p=0.5；单测覆盖）。
- **> 与 ≥**：所有候选点估计的 r 阈值判决用**严格 >**；只有 `P≥0.5`（冻结 reliability 语义）用 `≥`。
  两个边界都在 `tests/test_formula.py::test_strict_vs_ge_boundary` 与 `test_reliability_bin_semantics` 验证。

## 7. 四个候选点估计（**均未冻结**，逐条标注）

记 `q_i = conditional_quantiles_log[:,i]`（FP64，log1p(mm/h)，τ_i=(i+0.5)/32，严格递增），
`p = rain_prob`，`Q_i = expm1(q_i)`（条件分位，mm/h）。

| 候选 | 公式 | 语义 | 状态/标注 |
|---|---|---|---|
| **A** | `ŷ_A = p · mean_i(Q_i)` | 现有诊断代理（`models/quantile_v2/outputs.py:57 materialize_physical` 的 `p*q.mean`），物理空间 32 分位等权均值 | `EXISTING_DIAGNOSTIC_PROXY / NOT_FROZEN` |
| **B** | `p<0.5 → 0`；`p≥0.5 → expm1( Q_cond((p−0.5)/p) )`；`Q_cond` 在 log1p 空间对 τ_i 线性插值；`u<τ_0` 取支持下界 0.1 mm/h；p=0.5 ⇒ 0.1 mm/h | 混合分布中位数：`F(r)=(1−p)+p·F_cond(r)=0.5` 的反解 | `MIXTURE_MEDIAN / NOT_FROZEN` |
| **C** | `ŷ_C = p · expm1( mean_i(q_i) )` | 条件均值近似：32 分位等权积分在 **log1p 坐标**完成，尾部（τ>31/32）截断到 q32 | `CONDITIONAL_MEAN_APPROX_LOG_INTEGRAL / NOT_FROZEN`；[DESIGN_CHOICE] 见 §11-R6 |
| **D** | `P(R>r) = p · (1 − F_cond(r))`；`F_cond` 由 32 分位在 log1p 空间线性插值；事件判决 `P≥0.5`（附严格 >0.5 对照） | 概率式超阈值概率（发生率 × 条件生存函数） | `PROBABILISTIC_EVENT / NOT_FROZEN`；r > expm1(q32) 的像素标 **NOT_ESTABLISHED** |

候选 D 的支持规则：逐像素 `support ⇔ r ≤ expm1(q32_i)`（32 分位条件分布无法给出 q32 以上的质量）。
D 的分母在 `candidate_D[<r>].support` 中显式给出 `N_supported / N_not_established`；
混淆矩阵只在支持子集上给值，`status=ESTIMABLE_WITH_SUPPORT` 或 `NOT_ESTABLISHED_FOR_PART_OF_POPULATION`。
D 在 r=0.1 且 P≥0.5 时与 `OCC_P` 完全一致（单测强制验证），可作为概率链自检。

**所有候选只写入 `new_metrics`，绝不回馈 gate、模型选择或任何后续决策。**

## 8. 单位、缺测 mask、时间对齐

- 单位：物理量一律 **mm/h**；`conditional_quantiles_log` 为 `log1p(mm/h)`；`q32_physical=expm1(q32_log)`。
- 缺测 mask：`valid = imerg_valid & yunnan_region`（B0/B1 由 `read_imerg_local` 的 valid 与冻结 mask 组成；
  B2–B8 由 `Batch.valid` 与 `Batch.region` 组成）。新指标只用 `valid&region` 像素；被 mask 像素的 rate 可为 NaN，
  绝不进入任何 sum；冻结校验器在 `metrics.py:62 supervision(...)` 里同样拒绝 NaN/负值/零有效。
- 时间对齐：batch 逐 scene 带 `analysis_time`（B0/B1 用 `window_start`），冻结 `block_id` 以 UTC 字符串解析；
  每场景 6 个 satellite slot 的 nominal/obs_start/obs_end 由 reader 内 `TargetBinding.check_forecast` 校验
  （B2–B8，`stage4/data.py:195`）或 `Plan` 的 `CAUSAL_SIX_SLOT_ORDER`（B0/B1，`data.py:66`）。
  推理代码不对时间做任何重采样/位移。
- 掩膜广播：`NumericEvaluator.add` 显式拒绝任意 mask 广播（`validation.py:19 same_shape_device`）；新指标同样要求
  rate/valid/region 形状一致（`PointAccumulator.add` 会 broadcast-check）。

## 9. 失败处理与可复现性

- 任一 gate 指标超差、任一 reader/身份/SHA 校验失败、任一 OOM/异常 → `result.json` 记录 `FAILED`（含 traceback）
  且 supervisor 停止；不自动重试、不自动重放、不跳过进入下一个 run（`run-all` 默认 fail-fast）。
- 输出目录不允许覆盖（除 `_dry_check/` 可重建）；因此每个 run 的可复现实验只需删除该 run 的 output 子目录后重跑，
  但**科学上禁止**在已知 gate 失败后“调整后重跑”——需先定位推理链问题并报告。
- 所有 checkpoint/Dev 报告在 `run` 前做 SHA-256 校验（`--no-verify-sha` 仅为调试保留；默认校验）。
